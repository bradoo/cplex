# 跨境电商库存与运输模拟器

这个模拟器把跨境电商里的几个典型优化问题放在一个页面里：

- 仓库网络选择：开哪些海外仓，哪些市场由哪个仓履约
- 旺季缺口分析：需求上涨时，哪些市场会缺履约能力
- 临时扩容决策：扩容成本和丢单罚分哪个更划算
- 新市场进入决策：新国家市场先直邮试水，还是启用区域仓/本地 3PL
- 补货计划：空运、海运、库存、缺货之间如何取舍
- 多供应商采购分配：采购价、起订量、交期和可靠性之间如何取舍
- 跨仓库存调拨：海外仓之间库存不均时，如何在调拨、补货和缺货之间取舍
- 物流服务组合：本地仓、经济直邮、加急直邮如何混合使用
- SLA 敏感性分析：送达承诺从 3 天到 9 天时，成本和线路组合如何变化
- 多目标权衡：成本、时效、碳排和履约风险之间如何取舍
- 物流韧性预案：正常成本和故障不断供之间如何取舍
- 清仓折扣优化：库存积压时，如何选择折扣档并控制毛利损失

## 演示顺序

### 1. 严格 SLA

仓网模式选择：

```text
严格 SLA
```

推荐参数：

```text
需求倍率: 1.0
SLA 放宽天数: 0
未履约罚分: 50
```

讲解重点：

```text
当客户要求较快送达时，模型会倾向于启用区域海外仓。
固定成本更高，但能满足 US West、US East、UK、EU 等市场的时效要求。
```

典型结果：

```text
启用 Los Angeles 3PL、New Jersey 3PL、Rotterdam EU Hub
未履约订单为 0
```

### 2. 旺季缺口分析

仓网模式选择：

```text
旺季缺口分析
```

页面会自动切到：

```text
需求倍率: 1.25
```

讲解重点：

```text
需求上涨后，如果不允许扩容，模型不会只说“无解”，
而是通过未履约变量告诉我们缺口在哪里。
```

典型结果：

```text
UK 出现 500 单未履约
Rotterdam EU Hub 接近或达到容量上限
```

### 3. 旺季临时扩容

仓网模式选择：

```text
旺季临时扩容
```

推荐参数：

```text
需求倍率: 1.25
未履约罚分: 50
```

讲解重点：

```text
模型会比较临时扩容成本和未履约罚分。
如果扩容更便宜，就选择给瓶颈仓库购买额外容量。
```

典型结果：

```text
Rotterdam EU Hub 临时扩容 500 单
未履约订单降为 0
```

### 4. 补货参数试验

可以调整：

```text
空运周容量
海运提前期周数
未履约罚分
```

推荐演示：

```text
把空运周容量从 900 调到 1200
```

观察：

```text
补货缺货会减少或消失，但运输成本会上升。
```

再试：

```text
把海运提前期从 3 调到 2
```

观察：

```text
便宜海运更早到货，通常比单纯增加空运更划算。
```

### 5. 多供应商采购分配

仓网模式选择：

```text
多供应商采购分配
```

讲解重点：

```text
最低采购价不等于最低总风险。
供应商会有产能、起订量、交期和可靠性差异。
模型会把订单拆给多个供应商，而不是简单选一家最便宜的。
```

核心建模方式：

```text
最小化总成本 = 采购成本
             + 供应商启用成本
             + 缺货罚分
```

关键约束：

```text
每个 SKU 要覆盖需求和安全库存；
供应商有产能上限和起订量；
平均交期不能超过目标；
平均可靠性必须达标。
```

观察：

```text
模型可能同时选择低价供应商、稳定供应商和本地备份供应商。
这不是“犹豫”，而是在满足交期和可靠性约束下做最低成本组合。
```

### 6. 跨仓库存调拨

仓网模式选择：

```text
跨仓库存调拨
```

页面参数：

```text
选择这个场景后，右侧结果区顶部会出现“需求与库存参数”。
可以直接修改每个海外仓的初始库存和需求，再点击“重新求解”。
```

讲解重点：

```text
海外仓库存经常不均衡：有的仓爆仓，有的仓缺货。
模型会比较三种选择：
跨仓调拨、从国内补货、接受缺货罚分。
```

核心建模方式：

```text
最小化总成本 = 跨仓调拨成本
             + 国内补货成本
             + 缺货罚分
```

关键约束：

```text
每个仓库都要满足库存平衡；
跨仓调拨线路有容量限制；
国内补货总量有限；
期末库存和缺口都不能为负。
```

观察：

```text
模型会优先使用便宜、可行的近距离调拨；
跨洲调拨如果太贵，可能不如国内补货。
```

### 7. 新市场进入决策

仓网模式选择：

```text
新市场进入决策
```

讲解重点：

```text
进入新市场时，不一定一开始就要开本地 3PL。
如果订单量还不够大，固定成本可能吃掉本地履约节省的变动成本。
模型会在直邮试水、区域仓履约、本地 3PL 之间分配订单。
```

核心建模方式：

```text
最大化净贡献 = 销售毛利
             - 履约变动成本
             - 市场进入固定成本
```

观察：

```text
模型可能选择“部分直邮 + 部分区域仓”，既满足快速履约比例，又避免太早承担本地 3PL 固定成本。
```

### 8. 多目标权衡

仓网模式选择：

```text
多目标权衡
```

讲解重点：

```text
真实业务里通常不是单目标。
如果只看成本，模型会偏向便宜但慢的经济线路；
如果提高速度、碳排或风险的权重，模型会把部分订单切到海外仓或加急线路。
```

核心建模方式：

```text
总评分 = 物流成本
       + 速度权重 × 总送达天数
       + 碳权重 × 碳排放
       + 风险权重 × 预计风险订单
```

观察：

```text
同一批市场需求和路线容量下，权重不同，最优线路组合也不同。
这就是业务上说的“策略偏好”如何进入优化模型。
```

### 9. SLA 敏感性分析

仓网模式选择：

```text
SLA 敏感性分析
```

讲解重点：

```text
SLA 不是一句“越快越好”。
承诺 3 天、4 天、8 天、9 天，对成本和线路选择的影响完全不同。
这个例子会批量求解多个送达承诺档位，形成一条成本曲线。
```

观察：

```text
3 天承诺可能无解；
4-6 天通常需要本地仓或 DDP 加急；
8-9 天可以使用更多直邮，成本会明显下降。
```

适合对业务方说的一句话：

```text
每缩短一天承诺，都不是改一句页面文案，而是在改变履约网络和成本结构。
```

### 10. 物流韧性预案

仓网模式选择：

```text
物流韧性预案
```

讲解重点：

```text
精益方案只看正常月份的最低成本；
韧性方案会提前预留备份线路或备用仓容。
平时看，韧性方案可能多花一点钱；
但在海关延误、干线容量下降、旺季爆仓时，它能显著减少缺口。
```

核心建模方式：

```text
精益方案目标 = 正常履约成本

韧性方案目标 = 正常履约成本
             + 备份能力预留成本
             + 故障场景缺口罚分
```

观察：

```text
如果没有提前预留，故障时可能无法临时启用备份线路。
模型会把“平时省的钱”和“出事时缺货的损失”放在一起比较。
```

### 11. 清仓折扣优化

仓网模式选择：

```text
清仓折扣优化
```

讲解重点：

```text
清仓不是所有商品统一打 8 折。
不同 SKU 对折扣的需求弹性不同，库存压力和毛利也不同。
模型会给每个 SKU 选择一个折扣档，平衡销量提升、毛利损失、持有成本和品牌折损。
```

核心建模方式：

```text
最大化净贡献 = 销售收入
             - 商品成本
             - 剩余库存持有成本
             - 深折扣品牌罚分
```

观察：

```text
季节款可能需要深折快速消化；
小配件轻折就能带动销量；
毛利健康且库存压力不大的 SKU 可能不该打折。
```

## 页面指标怎么读

| 指标 | 含义 |
|---|---|
| 仓网总成本 | 仓库固定成本 + 履约变动成本 + 扩容/缺口相关成本 |
| 未履约订单 | 当前仓网和约束下无法满足的订单量 |
| 补货总成本 | 空运/海运成本 + 持有成本 + 缺货罚分 |
| 服务组合成本 | 本地仓、经济直邮、加急直邮混合后的总成本 |

## API

模拟器接口：

```text
POST /api/simulate
```

示例请求：

```json
{
  "scenario": "capacity_expansion",
  "demand_multiplier": 1.25,
  "sla_extra_days": 0,
  "unfulfilled_penalty": 50,
  "air_capacity": 900,
  "ocean_lead_time": 3
}
```

可选 `scenario`：

```text
strict_sla
soft_capacity
capacity_expansion
market_entry
supplier_sourcing
inventory_transfer
multi_objective
resilience
sla_sensitivity
markdown_clearance
```

## 适合对业务方说的一句话

```text
这个模拟器不是预测销量，而是在给定销量、仓容、运费和时效要求后，
计算怎样开仓、分仓、补货和选择物流服务，能让总成本或损失最小。
```
