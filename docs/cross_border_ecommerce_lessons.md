# 跨境电商优化场景讲义

这份文档把模拟器里的跨境电商场景整理成统一的讲课模式。每一课都回答五个问题：

```text
这个场景解决什么业务问题？
模型要决定什么变量？
优化目标是什么？
有哪些关键限制？
业务上应该怎么解释结果？
```

## 1. 严格 SLA

这个场景解决的是：客户要求较快送达时，企业应该开哪些海外仓，以及每个市场由哪个仓履约。

核心变量：

```text
open_warehouse[w]：是否启用仓库 w
ship[w,m]：仓库 w 给市场 m 发多少订单
```

目标函数：

```text
最小化总履约成本 = 仓库固定成本 + 单票履约变动成本
```

关键限制：

```text
每个市场需求必须满足；
仓库发货量不能超过容量；
超过 SLA 天数的线路不能使用。
```

业务判断句：

```text
严格 SLA 会逼迫企业使用更靠近客户的仓，成本上升换来更稳定的送达承诺。
```

## 2. 旺季缺口分析

这个场景解决的是：旺季需求上涨后，如果不扩容，哪些市场会出现履约缺口。

核心变量：

```text
open_warehouse[w]：是否启用仓库
ship[w,m]：仓库给市场发货量
unfulfilled[m]：市场 m 未履约订单量
```

目标函数：

```text
最小化总损失 = 仓库固定成本 + 履约成本 + 未履约罚分
```

关键限制：

```text
发货量 + 未履约量 = 市场需求；
仓库容量不能超过上限；
不满足 SLA 的线路不能使用。
```

业务判断句：

```text
缺口分析不是为了接受丢单，而是为了定位旺季瓶颈到底卡在市场、仓库还是线路。
```

## 3. 旺季临时扩容

这个场景解决的是：旺季到底该买临时仓容，还是接受部分未履约。

核心变量：

```text
extra_capacity[w]：仓库 w 临时扩容多少
unfulfilled[m]：市场 m 未履约订单量
ship[w,m]：仓库到市场的履约量
```

目标函数：

```text
最小化总成本 = 固定成本 + 履约成本 + 扩容成本 + 未履约罚分
```

关键限制：

```text
仓库发货量不能超过基础容量 + 临时扩容；
扩容只能发生在启用仓；
需求可以用未履约变量兜底。
```

业务判断句：

```text
当丢单损失高于扩容成本时，模型会主动买临时产能。
```

## 4. 库存前置分配

这个场景解决的是：哪些 SKU 应该提前放到海外仓，哪些继续从国内直邮。

核心变量：

```text
place[sku,market]：某 SKU 前置到海外仓的数量
direct_ship[sku,market]：某 SKU 继续直邮的数量
```

目标函数：

```text
最大化销售贡献 = 销售毛利 - 本地配送成本 - 仓储成本 - 直邮成本
```

关键限制：

```text
前置数量 + 直邮数量 = 市场需求；
每个海外仓体积容量不能超过上限。
```

业务判断句：

```text
海外仓不是越多越好，适合前置的是周转快、贡献高、时效价值明显的 SKU。
```

## 5. 新市场进入决策

这个场景解决的是：进入新国家市场时，应该先直邮试水，还是启用区域仓或本地 3PL。

核心变量：

```text
use_channel[c]：是否启用某个履约渠道
orders[c,m]：渠道 c 服务市场 m 的订单量
```

目标函数：

```text
最大化市场贡献 = 销售毛利 - 履约变动成本 - 市场进入固定成本
```

关键限制：

```text
每个市场需求必须满足；
每个渠道有容量上限；
每个市场必须达到最低快速履约比例。
```

业务判断句：

```text
新市场不是一上来就重资产铺仓，而是在固定成本和履约体验之间找进入节奏。
```

## 6. 天气风险建仓选址

这个场景解决的是：选择仓库地点时，是否应该考虑极端天气和中断风险。

核心变量：

```text
open_warehouse[w]：是否启用候选仓
ship[w,m]：仓库 w 给市场 m 发货量
```

目标函数：

```text
最小化风险调整后成本 = 仓库固定成本 + 履约成本 + 天气风险成本
```

关键限制：

```text
每个市场需求必须满足；
仓库容量不能超；
不满足 SLA 的线路不能用；
高天气风险仓承接订单比例不能过高；
整体平均天气风险不能超标。
```

业务判断句：

```text
天气风险可以被模型转成风险成本和风险约束，让选址不只看租金和运费。
```

## 7. 库存不足利润优先分配

这个场景解决的是：库存不够时，应该优先满足哪些 SKU 和市场。

核心变量：

```text
fulfill[sku,market]：给某 SKU、某市场分配多少库存
```

目标函数：

```text
最大化总贡献 = 单位贡献 × 履约数量
```

关键限制：

```text
每个 SKU 可用库存不能超；
履约量不能超过各市场需求；
每个市场有最低服务率。
```

业务判断句：

```text
库存不足时不能简单先到先得，要把库存分给更高贡献的订单，同时守住服务底线。
```

## 8. 补货情景分析

这个场景解决的是：空运、海运、库存持有和缺货之间如何取舍。

核心变量：

```text
order[lane,week]：每周通过某运输方式下单多少
ending_inventory[week]：每周期末库存
stockout[week]：每周缺货量
```

目标函数：

```text
最小化补货总成本 = 运输成本 + 库存持有成本 + 缺货罚分
```

关键限制：

```text
期末库存 = 期初库存 + 到货 - 需求 + 缺货；
空运和海运每周有容量限制；
期末库存要达到目标。
```

业务判断句：

```text
空运适合救急，海运适合提前规划，缺货罚分决定模型愿意为速度多付多少钱。
```

## 9. 多供应商采购分配

这个场景解决的是：供应商之间如何在采购价、起订量、交期和可靠性之间取舍。

核心变量：

```text
use_supplier[s]：是否启用供应商 s
buy[s,sku]：从供应商 s 采购 SKU 数量
shortage[sku]：SKU 采购缺口
```

目标函数：

```text
最小化采购总成本 = 采购成本 + 供应商启用成本 + 缺货罚分
```

关键限制：

```text
每个 SKU 要覆盖需求和安全库存；
供应商有产能和起订量；
平均交期不能超过目标；
平均可靠性必须达标。
```

业务判断句：

```text
最低价供应商不一定最优，交期和可靠性差会把便宜采购变成高风险采购。
```

## 10. 供应商评分体系

这个场景解决的是：选择供应商时，把资质、历史业务、风险、天气、售后和响应能力都纳入模型。

核心变量：

```text
use_supplier[s]：供应商是否入选
buy[s,sku]：从供应商采购多少
shortage[sku]：采购缺口
```

目标函数：

```text
最小化综合采购风险成本
= 采购成本 + 启用成本 + 质量/法律风险成本 + 天气/地理风险成本 + 缺货罚分 - 服务响应加分
```

关键限制：

```text
供应商评分、风险、可靠性、准时率和响应能力要过门槛；
供应商有产能和起订量；
单一供应商占比不能过高；
每个 SKU 要覆盖需求和安全库存。
```

业务判断句：

```text
供应商选择不是只比报价，而是把便宜、稳定、合规和响应速度放到同一张决策表里。
```

## 11. 采购现金流约束

这个场景解决的是：现金预算有限时，每个月该买哪些货、买多少。

核心变量：

```text
buy[sku,month]：每月每个 SKU 的采购量
inventory[sku,month]：月末库存
shortage[sku,month]：当月缺口
```

目标函数：

```text
最小化总成本 = 采购成本 + 库存持有成本 + 缺货罚分
```

关键限制：

```text
每月库存要滚动平衡；
每月现金支出不能超过预算；
采购付款要考虑本月付款和下月账期；
仓库总库存不能超过容量；
期末要保留最低库存覆盖。
```

业务判断句：

```text
缺货有时不是预测问题，而是现金流约束导致的采购节奏问题。
```

## 12. 整柜拼箱空运补货

这个场景解决的是：FCL、LCL 和空运应该如何组合补货。

核心变量：

```text
batches[mode,week]：每周选择几批空运、拼箱或整柜
inventory[week]：每周期末库存
stockout[week]：每周缺货量
```

目标函数：

```text
最小化补货成本 = 运输订货成本 + 库存持有成本 + 缺货罚分
```

关键限制：

```text
库存随提前期到货滚动平衡；
每种运输方式有每周批次数上限；
拼箱和整柜有固定费用和批量大小；
仓库容量和期末库存目标必须满足。
```

业务判断句：

```text
空运解决近期缺口，整柜解决远期成本，拼箱负责在速度和成本之间过渡。
```

## 13. 跨仓库存调拨

这个场景解决的是：一个海外仓库存过多、另一个海外仓缺货时，是否应该跨仓调拨。

核心变量：

```text
transfer[from,to]：从一个海外仓调到另一个海外仓的数量
replenish[warehouse]：从国内补货数量
shortage[warehouse]：仓库缺口
ending_inventory[warehouse]：期末库存
```

目标函数：

```text
最小化库存平衡成本 = 跨仓调拨成本 + 国内补货成本 + 缺货罚分
```

关键限制：

```text
每个仓库满足库存平衡；
跨仓调拨线路有容量限制；
国内补货总量有限；
期末库存和缺口不能为负。
```

业务判断句：

```text
跨仓调拨的价值在于把已经在海外的库存重新放到更需要它的位置。
```

## 14. 安全库存优化

这个场景解决的是：预算有限时，不同 SKU 应该选择什么安全库存水平。

核心变量：

```text
choose[sku,level]：SKU 选择 basic、standard 或 premium 安全库存
```

目标函数：

```text
最大化预算内的缺货保护价值
```

关键限制：

```text
每个 SKU 只能选择一个服务水平；
安全库存总成本不能超过预算。
```

业务判断句：

```text
安全库存不是平均撒钱，而是把保护预算优先给缺货损失更高的 SKU。
```

## 15. 稳健库存计划

这个场景解决的是：需求预测不准时，如何制定更抗波动的采购计划。

核心变量：

```text
buy[sku]：采购数量
leftover[sku,scenario]：不同需求场景下的剩余库存
stockout[sku,scenario]：不同需求场景下的缺货
```

目标函数：

```text
最小化稳健库存成本 = 采购成本 + 期望持有成本 + 期望缺货损失
```

关键限制：

```text
每个需求场景下都要满足库存平衡；
总仓容有限；
采购预算有限。
```

业务判断句：

```text
稳健库存不是押一个销量预测，而是在多个可能未来里都尽量不出大错。
```

## 16. Landed Cost 路径选择

这个场景解决的是：不能只看运费，而要比较到岸综合成本。

核心变量：

```text
use_route[r]：是否启用物流路径 r
orders[r,m]：路径 r 承担市场 m 的订单量
```

目标函数：

```text
最小化到岸成本 = 路径固定成本 + 运费 + 关税/清关成本
```

关键限制：

```text
市场需求必须满足；
路径容量有限；
平均时效必须满足 SLA。
```

业务判断句：

```text
物流路径选择要看 landed cost，DDU、DDP、保税仓的差异不只在运费。
```

## 17. 关税政策敏感性

这个场景解决的是：税率、免税门槛或 DDU 合规成本变化后，物流路径是否要切换。

核心变量：

```text
use_route[r]：不同政策情景下是否启用路径
orders[r,m]：不同政策情景下路径承接订单量
```

目标函数：

```text
每个政策情景都最小化：固定成本 + 运费 + 关税 + 清关/合规成本
```

关键限制：

```text
市场需求必须满足；
路径容量有限；
平均时效必须满足 SLA。
```

业务判断句：

```text
政策变化会改变最优物流结构，敏感性分析可以提前看到切换点。
```

## 18. 百分比 SLA 路径选择

这个场景解决的是：不是要求平均时效好看，而是要求一定比例订单在承诺天数内送达。

核心变量：

```text
use_route[r]：是否启用路径
orders[r,m]：路径 r 服务市场 m 的订单量
```

目标函数：

```text
最小化履约成本 = 路径固定成本 + 单票履约成本
```

关键限制：

```text
市场需求必须满足；
路径容量有限；
至少 X% 订单要在 N 天内送达。
```

业务判断句：

```text
百分比 SLA 比平均 SLA 更接近真实客户承诺，因为少数慢单不能被平均数掩盖。
```

## 19. SLA 敏感性分析

这个场景解决的是：送达承诺从 3 天放宽到 5 天、7 天、9 天，成本和线路组合如何变化。

核心变量：

```text
orders[route,market]：每个 SLA 档位下的路径订单量
```

目标函数：

```text
每个 SLA 档位都最小化：路径固定成本 + 单票履约成本
```

关键限制：

```text
每个市场需求必须满足；
路径容量有限；
至少指定比例订单在承诺天数内送达。
```

业务判断句：

```text
SLA 越紧通常越贵，敏感性分析可以告诉业务方“快一天”到底值多少钱。
```

## 20. 绿色物流成本/碳排

这个场景解决的是：在物流成本和碳排放之间如何取舍。

核心变量：

```text
orders[route,market]：各路线承接订单量
```

目标函数：

```text
最小化绿色物流成本 = 物流成本 + 碳价 × 碳排放
```

关键限制：

```text
市场需求必须满足；
路线容量有限；
平均时效必须满足 SLA。
```

业务判断句：

```text
低碳路线只有在不突破时效和容量约束时，才会成为可执行方案。
```

## 21. 多目标权衡

这个场景解决的是：成本、速度、碳排和风险同时重要时，如何放到同一个模型里比较。

核心变量：

```text
orders[route,market]：每条物流路径服务每个市场的订单量
```

目标函数：

```text
最小化综合评分 = 物流成本 + 速度权重 × 总送达天数 + 碳权重 × 碳排 + 风险权重 × 预计风险订单
```

关键限制：

```text
每个市场需求必须满足；
每条路径不能超过容量；
每个市场平均送达天数不能超过 SLA。
```

业务判断句：

```text
多目标优化不是找唯一正确答案，而是把管理层偏好变成可比较的权重。
```

## 22. 物流韧性预案

这个场景解决的是：正常情况下最便宜的方案，在故障发生时是否还能不断供。

核心变量：

```text
normal_orders[route,market]：正常方案订单量
disruption_orders[route,market]：故障场景订单量
reserve[route]：提前预留的备份能力
shortage[market]：故障时缺口
```

目标函数：

```text
精益方案：只最小化正常成本
韧性方案：最小化正常成本 + 预留成本 + 故障缺口罚分
```

关键限制：

```text
正常和故障场景都要满足需求平衡；
线路有正常容量和故障容量；
故障时只能使用平时铺好的能力和预留能力。
```

业务判断句：

```text
韧性不是免费保险，而是用少量预留能力换取故障时不断供。
```

## 23. 包装箱型与运费优化

这个场景解决的是：不同订单应该使用哪种箱型和包材，才能平衡运费、包材费和破损风险。

核心变量：

```text
assign[order_type,box]：每类订单使用某种箱型/包材的数量
```

目标函数：

```text
最小化包装履约成本 = 运输体积重成本 + 包材成本 + 预计破损成本
```

关键限制：

```text
每类订单必须选择装得下的箱型；
箱型有重量和体积限制；
整体预计破损率不能超过目标。
```

业务判断句：

```text
包装不是仓库细节，它会通过体积重、破损率和客户体验直接影响利润。
```

## 24. 渠道分配优化

这个场景解决的是：FBA、品牌 3PL、直邮等渠道之间如何分配订单。

核心变量：

```text
orders[channel,market]：渠道承接订单量
```

目标函数：

```text
最大化渠道利润 = 销售额 - 商品成本 - 履约成本 - 平台佣金
```

关键限制：

```text
市场需求必须满足；
渠道容量有限；
每个市场有最低快速履约比例。
```

业务判断句：

```text
直邮可能利润高，但如果时效不达标，就不能承担太多客户承诺。
```

## 25. 退货逆向物流

这个场景解决的是：退货件应该在本地翻新、转仓处理，还是报废回收。

核心变量：

```text
refurb_local[sku,region]：在本地翻新数量
transfer_refurb[sku,source,target]：转到其他区域翻新数量
scrap[sku,region]：报废或回收数量
```

目标函数：

```text
最大化退货回收价值 = 二次销售价值 + 回收价值 - 翻新/转运成本
```

关键限制：

```text
每个退货 SKU 必须被处理；
区域翻新产能有限。
```

业务判断句：

```text
退货不是只有损失，关键是让可恢复价值的商品进入正确处理路径。
```

## 26. 退货分级再销售

这个场景解决的是：退回来的商品按成色分到正价翻新、折扣销售、批发或回收渠道。

核心变量：

```text
assign[grade,sku,channel]：不同成色和 SKU 分配到各再销售渠道的数量
```

目标函数：

```text
最大化回收净价值 = 回收销售价值 - 检测/翻新/处理成本
```

关键限制：

```text
每个退货批次必须被处理；
每个渠道有处理容量；
C 级品不能进入正价翻新渠道。
```

业务判断句：

```text
退货优化的重点不是减少每一笔损失，而是让不同成色的退货去到最合适的价值回收路径。
```

## 27. 多平台库存分配

这个场景解决的是：库存紧张时，Amazon、独立站、TikTok Shop 和批发渠道之间应该优先满足谁。

核心变量：

```text
allocate[sku,channel]：SKU 分给每个平台的库存量
lost[sku,channel]：平台未满足订单量
```

目标函数：

```text
最大化平台净收益 = 平台净毛利 - 未满足订单罚分
```

关键限制：

```text
每个 SKU 分配量不能超过库存；
每个平台有履约容量；
关键平台有最低供货比例；
分配量 + 未满足量 = 平台需求。
```

业务判断句：

```text
库存不足时，最优分配不是平均分，而是按毛利、平台规则和服务底线排序。
```

## 28. 广告库存联动

这个场景解决的是：广告投放要不要受库存和履约能力约束。

核心变量：

```text
choose[sku,level]：每个 SKU 选择广告档位
fulfilled[sku]：实际履约销量
lost_sales[sku]：广告带来但无法履约的损失销量
```

目标函数：

```text
最大化广告后贡献 = 毛利 + 品牌增益 - 广告花费 - 缺货损失
```

关键限制：

```text
每个 SKU 只能选一个广告档位；
销量不能超过库存；
销量不能超过履约能力；
总广告预算有限；
强投 SKU 数量有限。
```

业务判断句：

```text
广告不是只负责拉需求，库存和履约跟不上时，广告会把增长变成缺货风险。
```

## 29. 客服售后排班

这个场景解决的是：跨时区、多语言客服工单如何安排内部客服、加班和外包。

核心变量：

```text
assign[agent,shift]：客服是否上某个班次
handled[agent,shift,language]：客服处理的语言工时
overtime[agent,shift]：加班小时
outsource[shift,language]：外包工时
```

目标函数：

```text
最小化服务成本 = 内部排班成本 + 加班成本 + 外包成本
```

关键限制：

```text
每个时段/语言的工单工时要被覆盖；
客服只能处理自己会的语言；
每人最多排指定班次数；
每班容量和加班上限；
外包占比不能过高。
```

业务判断句：

```text
客服排班优化是在服务 SLA、人员技能和外包成本之间找最低成本组合。
```

## 30. 订单波次排程

这个场景解决的是：仓库当天拣货和打包能力有限时，订单应该排到哪个出库波次。

核心变量：

```text
assign[group,wave]：订单组分配到哪个出库波次
pick_overtime[wave]：每个波次的拣货加班小时
pack_overtime[wave]：每个波次的打包加班小时
late_orders[group]：超过承诺截止波次的延期订单量
```

目标函数：

```text
最小化仓内执行成本 = 延期罚分 + 拣货加班成本 + 打包加班成本
```

关键限制：

```text
每个订单组只能分配到一个出库波次；
每个波次的拣货/打包工时不能超过常规产能 + 加班；
加班小时有上限；
晚于截止波次会产生延期订单。
```

业务判断句：

```text
仓内排程会直接影响履约 SLA，高优先级订单应该抢更早波次，低优先级订单可以后排。
```

## 31. 促销预算计划

这个场景解决的是：给定促销预算时，哪些 SKU 值得投促销。

核心变量：

```text
promote[sku]：是否促销某个 SKU
fulfilled[sku]：促销后实际履约销量
```

目标函数：

```text
最大化促销净收益 = 毛利贡献 - 促销花费
```

关键限制：

```text
履约销量不能超过促销后需求；
履约销量不能超过库存；
```


## 32. 促销预算敏感性

```text

```

目标函数：

```text
比较预算变化带来的净贡献变化
```

关键限制：

```text
每次求解都有预算限制；
每次求解都有库存限制；

```

业务判断句：

```text
促销预算敏感性分析，是帮我们找到“预算加到哪里最划算”，而不是证明预算越多越好。
```

## 33. 清仓折扣优化

这个场景解决的是：库存积压时，每个 SKU 应该选择哪个折扣档。

核心变量：

```text
choose[sku,discount]：SKU 是否选择某个折扣档
sell[sku,discount]：该折扣下卖出的数量
leftover[sku]：清仓后剩余库存
```

目标函数：

```text
最大化清仓净收益 = 销售收入 - 商品成本 - 持有成本 - 品牌折损罚分
```

关键限制：

```text
每个 SKU 只能选一个折扣档；
销量不能超过该折扣带来的需求上限；
销售量 + 剩余库存 = 当前库存；
清仓后库存不能超过仓容目标。
```

业务判断句：

```text
折扣不是越深越好，清仓的目标是用最小的毛利牺牲换最大的库存释放。
```


关键限制：

```text
每次求解都有需求约束。
```

业务判断句：

```text
未履约罚分是把丢单、差评、平台扣分和客户流失转成模型能理解的成本。
```
