# CPLEX 核心学习内容总结

10 页分享版

## 1. 我们到底在学什么

CPLEX 不是预测工具，而是数学优化求解器。

它回答的问题是：

```text
在一组业务限制下，怎样决策最好？
```

这次学习的主线：

```text
业务问题
-> 决策变量
-> 目标函数
-> 约束条件
-> CPLEX 求解
-> 业务解释
```

学会这条链路，比记住某一个 API 更重要。

---

## 2. 优化模型的三件套

每个 CPLEX 模型都可以拆成三部分：

```text
变量：模型可以决定什么
目标：模型想让什么最好
约束：模型必须遵守什么规则
```

例子：

```text
排班问题
变量：谁哪天上班
目标：尽量公平、少缺人、低成本
约束：每天人数、员工可用性、最多班次、技能要求
```

这也是以后看任何优化模型的第一反应。

---

## 3. 从简单模型开始：背包、运输、选址

我们先学了三个经典问题：

```text
背包问题：选哪些物品，让价值最大
运输问题：从哪里发到哪里，让运输成本最低
仓库选址：开哪些仓、怎么分配客户，让总成本最低
```

它们分别对应三类常见变量：

```text
0/1 变量：选或不选、开或不开
连续变量：发多少、采购多少、分配多少
混合变量：既有开关决策，也有数量决策
```

跨境电商和排班模型，本质上都是这些基础结构的业务升级版。

---

## 4. 排班模型：把管理规则变成约束

排班是最容易理解的业务优化问题之一。

核心问题：

```text
每天需要几个人？
每个人哪天可用？
每个人最多上几天？
是否需要关键技能？
怎样排既满足需求又尽量公平？
```

模型表达：

```text
变量：work[employee,day]
目标：最小化公平性差距、缺口、成本
约束：覆盖需求、员工可用性、最大班次、技能覆盖
```

关键收获：

```text
业务规则不是写死在人工经验里，而是可以明确写成模型约束。
```

---

## 5. 软约束：从“无解”变成“最小损失方案”

真实业务里，规则经常互相冲突。

比如：

```text
周末需要 5 个人
但可用员工只有 3 个
硬约束模型会直接无解
```

软约束的做法：

```text
允许缺口变量存在
但给缺口设置很高罚分
```

这样模型会输出：

```text
最少缺几个人
缺口发生在哪几天
为了减少缺口牺牲了哪些次要目标
```

业务价值：

```text
软约束不是放松管理，而是把冲突翻译成可解释的损失。
```

---

## 6. 多目标、罚分权重和分阶段优化

真实决策通常不是单目标。

常见目标会互相冲突：

```text
成本最低
服务最好
员工更公平
偏好命中更多
缺口更少
风险更低
```

三种处理方式：

```text
多目标权重：把多个目标放进同一个评分函数
罚分权重：给不同违规行为设置不同代价
分阶段优化：先保最重要目标，再优化次要目标
```

关键理解：

```text
优化模型不是替业务做价值判断，而是把业务优先级清楚地写出来。
```

## 7. 工程化：从脚本到系统

学习不只停留在一个 Python 脚本。

我们逐步做了：

```text
CSV 数据输入
情景分析
结果导出
自动解释报告
实验记录
性能基准
REST API
Web 交互页面
自动化测试
```

这说明优化模型可以从“本地演示”走向“业务系统”。

系统化以后，模型可以回答：

```text
这个方案为什么这样排？
换一组参数会怎样？
结果能不能导给别人？
后续改代码会不会破坏已有行为？
```

## 8. 跨境电商：把优化扩展到供应链

跨境电商模拟器把同一套建模思想扩展到 35 个场景。

四大类：

```text
仓网与履约：开仓、分仓、SLA、扩容、天气风险
补货与库存：供应商、现金流、整柜/拼箱/空运、调拨、安全库存
物流路径与服务：DDU/DDP、Landed Cost、关税、SLA、碳排、韧性
经营动作：退货、广告、促销、清仓、客服、订单波次、看板
```

共同逻辑：

```text
给定需求、库存、成本、时效和约束，
计算怎样决策能让成本最低、风险最小或净贡献最大。
```

---

## 9. 最重要的业务表达方式

以后讲任何 CPLEX 模型，都可以用同一个框架。

```text
这个模型解决什么问题？
模型能决定什么？
它想优化什么？
它必须遵守什么？
结果对业务意味着什么？
```

例子：订单波次排程

```text
问题：订单应该排到哪个出库波次
变量：assign[group,wave]
目标：延期罚分 + 拣货/打包加班成本最低
约束：产能、加班上限、截单波次
解释：仓内执行能力也会影响履约 SLA
```

这是从“会写代码”到“会讲模型”的关键。

---

## 10. 学完 CPLEX 后真正带走什么

最终沉淀的不是某个 demo，而是一种决策思维：

```text
把复杂业务拆成变量、目标和约束
把经验判断变成可计算规则
把冲突和取舍变成可解释结果
把单次求解扩展成情景分析和系统能力
```

一句话总结：

```text
CPLEX 的价值不是替人拍脑袋，
而是让业务决策在约束清楚、目标清楚、取舍清楚的基础上变得可计算。
```

下一步可以继续深入：

```text
更大的数据规模
更真实的业务约束
更稳定的 API 服务
更友好的可视化解释
```
